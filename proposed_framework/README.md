# Proposed Framework

This folder contains the core implementation of the proposed hierarchical battery metadata reconstruction framework.

The framework reconstructs key battery metadata from short-pulse voltage responses, including:

* material-capacity class;
* state of charge (SOC);
* state of health (SOH).

The proposed model follows a hierarchical reconstruction order:

```text
Material-capacity classification → SOC estimation → SOH estimation
```

This folder contains the data-processing utilities, model definitions, training functions and the main script used to train and evaluate the proposed framework.

## Main entry point

### `run_proposed_framework.py`

This is the main script for running the proposed framework.

It is responsible for loading data, building model inputs, training the hierarchical model, evaluating the trained model and saving checkpoints/results.

Typical usage from the repository root:

```bash
python proposed_framework/run_proposed_framework.py
```

This script should be run before the post-training analysis scripts in `analysis/`, because the analysis scripts reload the checkpoints generated by the proposed framework.

Typical outputs are saved under:

```text
results/proposed_framework/
```

Depending on the configuration, outputs may include cached data, normalization statistics, trained checkpoints and metric summaries.

## Data processing

### `data/build_dataset.py`

This file contains utilities for building training and testing datasets from the raw Excel files under the repository `data/` folder.

It handles the construction of data tables from different material-capacity groups, SOC sheets and pulse-width files. The resulting arrays and metadata are used by the proposed framework for model training and evaluation.

### `data/feature_builder.py`

This file contains feature-construction utilities.

The raw voltage-response features are stored as `U1` to `U41`. This module converts the voltage-response sequence into the structured input representation used by the proposed framework.

Depending on the configuration, the feature representation may include information such as voltage-response values, voltage-jump-related features and baseline voltage information.

### `data/pulse_dataset.py`

This file defines the PyTorch dataset used by the proposed framework.

It wraps the processed voltage-response features, material labels, SOC labels, SOH labels and pulse-related metadata into a format that can be used by PyTorch `DataLoader`.

## Model components

### `models/encoder.py`

This file defines the encoder network used to extract latent electrochemical features from the structured voltage-response input.

The encoder maps the short-pulse voltage representation into a learned feature representation that is shared by downstream material classification, SOC estimation and SOH estimation modules.

### `models/conditional_flow.py`

This file implements the conditional-flow estimator used for uncertainty-aware SOC and SOH reconstruction.

Unlike a deterministic regression head, the conditional-flow module models a predictive distribution conditioned on upstream information. This allows the framework to estimate SOC and SOH while preserving uncertainty across diagnostic stages.

### `models/hierarchical_model.py`

This file defines the full hierarchical model.

It combines the encoder, material classifier, SOC estimator and SOH estimator into one framework. The model follows the material-to-charge-to-health reconstruction order, where downstream predictions are conditioned on upstream diagnostic information.

## Training and evaluation

### `training/trainer.py`

This file contains training-loop utilities for optimizing the proposed framework.

It handles epoch-level training, model updates, checkpointing-related operations and other training procedures used by `run_proposed_framework.py`.

### `training/evaluator.py`

This file contains evaluation utilities.

It computes classification and regression metrics, converts normalized SOC/SOH predictions back to raw units when needed, and evaluates the model on validation or test data.

### `training/losses.py`

This file contains loss functions used during model training.

The losses may include material-classification loss, SOC/SOH reconstruction losses and conditional-flow-related objectives.

## Package files

### `__init__.py`

This file marks `proposed_framework/` as a Python package.

The `__init__.py` files inside subfolders such as `data/`, `models/` and `training/` serve the same purpose and allow modules to be imported across the repository.

### `__pycache__/`

These are automatically generated Python cache folders. They do not contain source code and should not be edited manually or committed to the repository.


A typical workflow is:

```text
1. Prepare the Excel data under data/
2. Run proposed_framework/run_proposed_framework.py
3. Save trained checkpoints and metric summaries under results/proposed_framework/
4. Run analysis scripts if per-sample prediction tables are needed
5. Run figure scripts to generate manuscript figures
```

## Notes

* Run scripts from the repository root to keep relative paths consistent.
* Keep the raw data under the top-level `data/` folder.
* Generated checkpoints, cached files and result tables should be saved under `results/`.
* Post-training analyses should be run from the `analysis/` folder scripts rather than being added directly to the training loop.
